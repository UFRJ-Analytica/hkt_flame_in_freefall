# Specialist workspace — integration contract v1

## Ownership and objective

Hermes owns new Python analysis/export scripts, their tests, and `public/data/saffire/specialist-workspace.json`. The frontend agent owns `src/`, interface tests, and frontend integration. Neither edits the other's files. Preserve the existing registry and calibration scripts. No paid APIs, new datasets, or physical defaults are required.

The specialist journey is: select evidence → inspect measured versus simulated quantities → compare experiments without claiming causality → construct exploratory habitat alternatives → export/reproduce a reviewable dossier. Additional animations are not additional validated physical models.

## Static data interface

Fetch `/data/saffire/specialist-workspace.json`. It is generated by `scripts/build_specialist_workspace.py` from the exact bytes of the registry and its nine model artifacts. Do not calculate missing experimental trajectories in the browser. Loading failure must be visible; do not silently substitute an embedded scientific registry.

Top level:

- `schemaVersion: 1`
- `generatedBy: "scripts/build_specialist_workspace.py"`
- `registry: {path, sha256}`
- `artifacts: [{path, sha256}]`
- `trials`: the existing nine registry trial objects, unchanged except an additive `analysis` property.
- `comparisons`: all unordered pairs, each with `trialIds`, `observableCompatible`, `speedDeltaMmS`, `speedDeltaPct`, `conditionDiffs`, `interpretation`, and `warnings`.
- `limitations`: explicit dataset-wide limits.

`trial.analysis`:

- `reviewStatus: "review-required" | "usable-with-limitations"`. S2 is review-required, not absent.
- `capabilities: {observedTrajectory: boolean, pairedTrajectory: boolean, habitatAnchor: boolean}`. Capability is not validation or physical transfer eligibility.
- `validationSummary: {kind, independentExternalValidation: false, note}`.
- `speedComparison`: null, or `{observedMmS, simulatedMmS, signedErrorPct, absoluteErrorMmS, positionMaeReportedMm, sourceField}`. This describes the saved validation window and selected model, not a newly trained model. Reported positional MAE is not recomputed from a median curve.
- `trajectory: {status: "available" | "unavailable", observableKind, modelKind, relationToRegisteredModel: "same-model" | "baseline-not-registered-model" | null, timeOrigin, sourceFields: string[], points: [{timeS, observedMm, simulatedMm: number | null}], note}`. Image-neighborhood artifacts can contain only the OLD longitudinal baseline's paired trajectory: label that explicitly; never plot it as the new neighborhood model.
- `missingData: string[]`, `warnings: string[]`.

Additive diagnostics: each available trajectory also exposes `metrics: {pointCount, pairedPointCount, timeSpanS, positionMaeMm, positionRmseMm, positionBiasMm, observedOlsSpeedMmS, simulatedOlsSpeedMmS, note}` and every point has `residualMm` (simulated minus observed). These metrics are recomputed from the stored plotted points; they are NOT the reported across-strip MAE in `speedComparison`. Missing trajectories have `metrics: null`.

Comparisons use the FIRST registry observable (the documented primary window), never an average of different methods. Rates with different observable kinds have null speed deltas. Even same-kind rates remain descriptive comparisons, NOT causal estimates or independent validation. `conditionDiffs: [{field, left, right, status: "same" | "different" | "unknown"}]`; absent pressure is unknown, not equal to 1 atm. O2 point and documented range are represented together, without invented tolerance. `interpretation` is always `"descriptive-not-causal"`.

## Frontend acceptance

1. Discoverable gallery for all nine records, filter by material/campaign/observable/data availability/review state. S2 stays visible with its gate.
2. Detail workspace with conditions, original sources, conflicts, model identity, measured/simulated speeds and provenance.
3. Comparison for 2+ trials: synchronized curves only where available, explicit time origins, distinguish baseline curves from selected-model summary metrics, show condition confounds. Unsupported curves show an informative empty state, not synthetic lines.
4. Specialist habitat A/B alternatives: save named scenarios, duplicate, edit, compare with identical seeds and horizon, show reference trial and gate per scenario. State which controls change source selection versus which have a modeled physical response. Do not interpret unknown-material stopping as a demonstrated barrier.
5. Dossier export: selected IDs, exact artifact hashes, conditions, selected model, metrics, warnings and comparison. Frontend may export its own same-data JSON/CSV/Markdown; offline Python provides a reference implementation.
6. Import/reproduction: validate complete inputs, enumerate mismatches, reject malformed files before state mutation. Do not claim identical fields from equality of just two aggregate metrics. Decorative fire/smoke is labeled illustrative at point of use.
7. No physical corrections for O2, pressure, gravity, radiation, smoke concentration, or suppression without a separately justified and tested model. Variation across random seeds is not experimental uncertainty.

## Reproduction

Python (stdlib only): `python scripts/build_specialist_workspace.py`.

Subset dossier: `python scripts/build_specialist_workspace.py --trial SAFFIRE-I-S1 --trial SAFFIRE-III-S1 --dossier-dir .scratch/specialist-dossier`.

Tests exercise the published dataset and exported dossier seams, additive preservation, exact artifact identity, observed/model curve identity, missing data, incompatible observables, comparison signs and invalid input rejection. Frontend tests exercise gallery → detail → comparison → habitat A/B → export/import.

The Python dossier contains `dossier.json`, `metrics.csv`, `trajectories.csv`, `comparisons.csv`, and `dossier.md`. `dossierId` is SHA256 of the UTF-8 indented JSON payload (LF, trailing newline) before adding that field. It is an integrity fingerprint, not an authenticity signature. `--verify-dossier .scratch/specialist-dossier/dossier.json` checks self-integrity and the full selected dataset against current exact inputs; status `identical` concerns the evidence dossier, NOT a rerun of the habitat engine. The generator's source fingerprint explicitly normalizes CRLF→LF; experimental artifact fingerprints never normalize bytes.

Verifier failures: incomplete/mistyped nested fields, invalid hashes, nonfinite scientific numbers, invalid dimensions or oxygen ranges are rejected with a field-specific error. Well-formed differing dossiers return `different-inputs-or-results` and `mismatches: [{path, expected, received, kind}]`, where paths are JSON pointers and kind distinguishes `input-identity`, `derived-results`, and `dataset-metadata`. Extra/missing fields carry a reason; JSON object key order alone is not a scientific difference. A self-consistent digest does not prove current source identity. CLI exit codes are 0 for identical, 2 for a well-formed mismatch, and nonzero for invalid input.
